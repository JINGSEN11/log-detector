# P1-2 规则与人工研判对比

## 当前状态

新增离线对比工具 `backend/src/test/java/com/csys/logdetector/detection/AnalysisComparisonTest.java`，不会自动调用模型或读取数据库。已有 31 个合成规则场景及多标签指标见本目录 `P1-2-规则评测报告-v2.json`。当前项目的研判没有攻击/正常结构化判决，不能把 confidence 或 MODEL 来源等同于分类；本工具比较的是“规则”与“规则 + 人工阅读模型研判”的工作流，不是模型自主分类能力。

本目录 `P1-2-人工研判对比例子.json` 与 `P1-2-人工研判对比演示报告.json` 是**虚构示例**，没有真实模型结果，不能作为模型有效性结论。真实模型对比尚未执行，调用前需授权及评估费用。

## 数据与方法

将场景的真实标签与分析人员的模型研判阅读结论分别独立记录，建议不同人员盲标并保留分歧仲裁。规则仅表示是否有命中，不能把规则标注直接当作攻击真值；原 31 个规则样本需要独立补充攻击/正常/不确定真值。输入 JSON 的字段：

- `datasetVersion`、`runId`：非空字符串，标识数据版本与本次评测。
- `cases`：非空数组，每个案例包含唯一的匿名 `id`、`gold`（`ATTACK`、`BENIGN`、`UNCERTAIN`）、`ruleHit`（布尔值）及 `source`。
- 命中后模型有效结果用 `source=MODEL`，并由**人工**填写 `review`（`ATTACK`、`BENIGN`、`UNCERTAIN`）；未命中用 `NO_HIT` 且不能填 review；降级 `RULE_FALLBACK`、未请求 `NOT_REQUESTED`、出错 `ERROR` 均保留规则正类、不填 review。
- 不要把原始日志、模型全文、账号密钥或敏感内容放入输入；工具报告仅输出白名单字段，不输出自由文本。

按场景做二分类：规则命中为正，未命中为负；在 MODEL 样本使用人工 review，其余沿用规则结论。`gold=UNCERTAIN` 的样本不计入任何指标；`review=UNCERTAIN` 从配对对比剔除，数量单列。报告 `rulesAllEligible` 是所有 gold 确定样本的规则基线；`rulesPaired`、`assistedPaired` 使用相同的确定样本进行公平配对。FP/FN 与 precision/recall/F1 为二分类场景指标，**不能直接与原先场景×规则的多标签 micro 指标比较**。分母为零显示 null。报告 `sources` 和 `excluded` 给出覆盖和排除情况。

## 复验示例

从项目根目录 PowerShell 执行，输出文件名必须不存在：

```powershell
mvn -f backend/pom.xml -Dtest=AnalysisComparisonTest "-Dcomparison.input=<项目根>/proceed/代码验收/P1-2-人工研判对比例子.json" "-Dcomparison.output=<项目根>/proceed/代码验收/P1-2-人工研判对比复验.json" test
```

预期 `Comparison: total=6, eligible=5, paired=4` 和 `BUILD SUCCESS`。打开报告：`rulesPaired.fp=2`，`assistedPaired.fp=1`，`assistedPaired.fn=1`，`excluded` 中真假值不确定和人工判定不确定各 1。此为模拟数据，仅验证工具计算。
